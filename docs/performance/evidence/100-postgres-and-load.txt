WHY THIS DOES NOT INVALIDATE THE MEASUREMENTS
--------------------------------------------------------------------------------
This investigation deliberately avoids wall-clock as the primary metric. The
three primary signals collected at every N are:

  * shared hit / shared read counts   -- a deterministic count of buffer
                                         accesses, independent of CPU speed
  * actual vs estimated row counts    -- a planner decision, a boolean-ish
                                         outcome rather than a timing
  * the NAME OF THE INDEX selected for the claims/evidence subplans
                                         -- the actual thing under
                                         investigation

None of these scale with host contention. Execution time is recorded for
context only and is explicitly NOT used to locate the cliff; see STEP 5, where
the switch is located by index name and buffer count.

Caveat recorded honestly: execution times in 10N-plan-NNNN.txt and 103/107
files carry whatever contention existed at the time and should not be compared
across runs of the whole sweep. Buffer counts and index names are the
load-independent signal.
