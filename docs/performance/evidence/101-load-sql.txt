--------------------------------------------------------------------------------
BOUND PARAMETERS  (api/services/memory.py:456)
--------------------------------------------------------------------------------
        {"c": corpus_id, "path": path, "at": _timestamp(as_of)}

_corpus_id_   -> :c
_path_        -> :path      (None for a whole-corpus load)
_as_of_       -> :at        (None for "latest")

The `CAST(:x AS <type>) IS NULL OR ...` idiom exists so that a single SQL
string with fixed bind names serves both the path-filtered and whole-corpus
case. It also matters for this investigation: the params are always bound,
never inlined, so asyncpg sees a parameterised statement and PostgreSQL may
plan it generically. See 106-plan-cache-mode.txt.
