  F) WHAT ACTUALLY MOVED
  ----------------------------------------------------------------------------------
  V4 is the only variant that changes a plan in the useful direction, and only
  between N=500 and N=1000 -- the band where the cliff bites:

      N=1000   V0  1,073,302 shared hit   755.2 ms   CLAIMS corpus-only, rf=999
               V4      2,457 shared hit   104.3 ms   437x fewer buffers, 7.2x faster
      N= 750   V0    598,782 shared hit   377.5 ms
               V4      1,851 shared hit    65.3 ms   323x fewer buffers, 5.8x faster
      N= 500   V0    267,714 shared hit   174.3 ms
               V4      1,674 shared hit    55.1 ms   160x fewer buffers, 3.2x faster

  ...and it is 11x-14x SLOWER than production everywhere below that:

      N= 300   V0    105,935 shared hit    64.7 ms
               V4     99,762 shared hit   857.2 ms   13.2x SLOWER
      N= 250   V0     71,599 shared hit    55.3 ms
               V4     68,807 shared hit   611.4 ms   11.1x SLOWER
      N= 100   V0      9,621 shared hit     8.8 ms
               V4      8,589 shared hit    99.1 ms   11.3x SLOWER

  V4 at N=300 is 857.2 ms, i.e. as bad as V0 at N=1000 (755.2 ms). The cliff did
  not disappear; it moved from N=500..1000 down to N=100..300. That is a
  relocation, not a fix.

  Cause, from 114-plans-n00250.json / 114-plans-n00500.json:
    - at N=500+ the planner Hash Joins the pre-aggregated derived tables (good);
    - at N<=300 it substitutes them as a correlated Nested Loop inner, re-running
      the full GROUP BY once per outer row (Actual Loops = N). At N=250 the plan
      shows three Nested Loops with the Sorted aggregates executed 250 times.
  V2 has the mirror-image failure: the CTE is materialised exactly once, so it
  has almost no buffer cost, but the planner joins it back with a Nested Loop +
  CTE Scan with Actual Loops = N (see 114-plans-n01000.json), which is O(N^2)
  tuple comparisons that never touch a shared buffer. That is why V2 posts the
  lowest shared-hit numbers in the whole table and still loses on wall clock.
