=== DIAGNOSIS ===
The gate logic itself is correct (A, B, C all behave as specified).
It is broken by the isolation wrapper, which is the DEFAULT path:

  _measure_isolated() builds the child argv as
      --sizes N --repeats R --out PATH --quiet
  and omits --max-load. The child therefore re-derives the threshold from
  env MP_MAX_LOADAVG (default 0.5), discarding the parent's CLI value.

  Consequence on this host (load 1.48-1.69, threshold 0.5):
    * --max-load 999  -> child still gates at 0.5, fires, exits 2
    * --max-load 0.001 -> child still gates at 0.5, fires, exits 2
  In both cases subprocess.run(check=True) raises CalledProcessError, the
  parent dies with a traceback and exit status 1, and NO artifact is written.
  The intended behaviour (clean exit 2 + host_load/CONTENDED artifact)
  is unreachable while isolation is on, which is the default.

Two distinct defects:
  1. --max-load is not forwarded to the isolated child.
  2. The gate runs in the child, where a non-zero exit is an error to the
     parent rather than a publish decision. The parent already samples
     os.getloadavg() and owns the artifact, so the child should never gate.

Not fixed here: the task forbade editing source files. A one-line forward of
--max-load in _measure_isolated would restore the high-threshold case, but
the low-threshold case still needs the child to stop gating, or the parent
to tolerate a child exit of 2.
